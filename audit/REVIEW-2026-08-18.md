### §3 未執行的理由（建議保留現行綱要）

規格要求 `id / name_zh / name_jp / city(slug) / category(英文) / stay_mins / tags / address`，
實作是 `name / name_ja / city(中文) / category(中文 7 類) / duration / activities+dishes / notes`，
且 `data/*.json` 按城市切（9 檔）而非按類別切（4 檔）。

- 現行欄位比規格**更豐富**（`hours / price / ticket / cuisine / winter / reason` 都在前端使用中）
- 三個前端檔全部照現行欄位讀取，改名需同時動 4 個檔與 143 筆資料，功能收益為零
- `city` enum 若照規格只有 5 個 slug，**放不下**行程實際造訪的北九州（下關／門司）與熊本（2/2 B 案）
- 唯一真正有價值的缺口是 **`address`**（現場找路用），但 143 筆地址無法憑空生成，需逐筆查證才能加

要照規格重構的話建議分兩步：先加相容層（同時輸出新舊欄位），再切換前端讀取。
